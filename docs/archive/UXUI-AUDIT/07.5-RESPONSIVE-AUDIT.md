## บทสรุปผู้บริหาร (อ่าน 30 วินาที)

ROS ใช้ **responsive architecture 2 แกนที่แยกหน้าที่ชัดเจน** (พบจากการนับ breakpoint จริง):
1. **`sm:` (640px) + `lg:` (1024px)** — คุม *layout ภายใน* (กริด/คอลัมน์) ไม่ขึ้นกับชนิด pointer
2. **custom `mouse:` / `touch:`** — สลับ *shell* ตาม **input method** ไม่ใช่แค่ความกว้างจอ
   ```
   mouse: (min-width:768px) and (not (any-pointer:coarse))  → desktop shell (sidebar rail)
   touch: (any-pointer:coarse)                              → mobile shell (bottom-nav)
   ```

นี่คือ **ONE design system จริง** — token เดียว, component เดียว (`ui.tsx`), ข้อมูลชุดเดียว เรนเดอร์ต่างรูปแบบตามบริบท (`ListView` = ตาราง desktop / การ์ด touch). ผู้ใช้รู้สึกว่า "ระบบเดียวกัน" ทุกอุปกรณ์ ✅

**ช่องว่างจริง = touch target บางตัว 36px (ต่ำกว่า 44px) + a11y polish (skip-link/aria-current)** ไม่ใช่ layout พัง

## 1. หลักฐานเชิงปริมาณ (นับจากโค้ดจริง)

### 1.1 การใช้ breakpoint
| prefix | admin | public | ความหมาย |
|---|---|---|---|
| `sm:` (640) | 55 | 28 | layout ภายใน (กริด/คอลัมน์/typography) |
| `mouse:` | 34 | 0 | สลับ shell + density (admin เท่านั้น) |
| `lg:` (1024) | 5 | 28 | public: 3 คอลัมน์บน desktop |
| `md:` (768) | 3 | 0 | ใช้น้อยมาก |
| `xl:` | 1 | 0 | แทบไม่ใช้ |

> **ข้อสรุป:** admin ขับด้วย **input-based** (mouse/touch) เป็นหลัก · public ขับด้วย **width-based** (sm/lg) แบบ marketplace ทั่วไป — เหมาะกับธรรมชาติของแต่ละแอป

### 1.2 การจัดการ viewport มือถือ (พบจริง)
| เทคนิค | ที่ใช้ |
|---|---|
| `100dvh` / `max-h-[90dvh]` | Modal, GlobalSearch overlay (กัน address-bar/คีย์บอร์ดมือถือดันจอ) |
| `env(safe-area-inset-bottom)` | bottom-nav, Modal footer (กัน notch/home-indicator iOS) |
| `field` 16px มือถือ → 14px `sm:` | กัน iOS auto-zoom ตอน focus input |
| `viewport-fit=cover` + ไม่ล็อกซูม | layout (a11y: ผู้ใช้ซูมได้) |

### 1.3 overflow / horizontal scroll (ความเสี่ยงล้นจอ)
พบ `overflow-x-auto` **เพียง 4 จุด — ทั้งหมดตั้งใจและคุมแล้ว:**
| ไฟล์ | จุด | คุมอย่างไร |
|---|---|---|
| `ui.tsx:442` | ตาราง ListView | เฉพาะ `mouse:` (desktop) |
| `ui.tsx:315` | Segmented chips | `max-w-full` + scroll ในกล่อง |
| `notifications:171` | filter chips | scrollbar ซ่อน + scroll-smooth |
| `FeaturedCarousel:84` | carousel | `snap-x snap-mandatory` + scrollbar ซ่อน |
- `* { min-width: 0 }` ใน globals (ทั้งสองแอป) → กัน flex/grid child ดันล้น
- `truncate` ใช้แพร่หลายทุกหน้า list/detail → ข้อความยาวไม่ดันเลย์เอาต์
- **สรุป: ไม่พบ horizontal scroll โดยไม่ตั้งใจ** ✅

## 2. Responsive ต่ออุปกรณ์ (ตาม 4 ช่วง)

### 📱 Mobile 320–767px — **A−**
- shell: bottom-nav ลอย 5 ช่องแบบ IG + drawer โปรไฟล์ + pull-to-refresh
- `ListView` → การ์ด (grid-cols-1), Modal กึ่งกลาง 100dvh, StickyCTA (public)
- field 16px กัน zoom, footer safe-area
- **เสี่ยง:** การ์ด + ปุ่ม action `btn-sm` (36px) เล็กกว่ามาตรฐานสัมผัส (ดู §4)

### 📲 Tablet 768–1023px — **B+**
- **ตรรกะจริง:** iPad/แท็บเล็ต = `any-pointer:coarse` → **mobile shell เสมอ** (แม้จอกว้าง/ต่อคีย์บอร์ด)
- ได้ประโยชน์: `sm:grid-cols-2` → การ์ด 2 คอลัมน์ (ใช้พื้นที่คุ้ม), public `sm:grid-cols-2`
- **ข้อสังเกต (design tradeoff ที่ตั้งใจ):** iPad Pro แนวนอน (เช่น 1366px, touch) ก็ยังเป็น bottom-nav (max-w-md กลางจอ) ทั้งที่จอกว้างพอจะวาง sidebar ได้ → เป็นการเลือก "touch-first" ที่ถูกต้องตามหลัก แต่ power-user บน iPad+คีย์บอร์ดอาจอยาก sidebar (ดู §9 ข้อเสนอ optional)

### 💻 Desktop 1024–1439px — **A−**
- shell: sidebar rail 84px (`mouse:grid-cols-[84px_1fr]`) + header (search/bell/profile)
- `ListView` → ตารางเต็ม, hover ทั้งแถว, density กระชับ
- เนื้อหา admin จัด `max-w-4xl/5xl` กึ่งกลาง — อ่านสบาย ไม่ยืดเต็มจนล้าตา

### 🖥️ Large Desktop 1440px+ — **B+**
- admin: เนื้อหา cap ด้วย `max-w-*` (ดี — ไม่ยืดเกินอ่านยาก) · sidebar คงที่ 84px
- public: `max-w-content` (1200px) กึ่งกลาง
- **ข้อสังเกต:** ที่ ≥1440 ใช้ความกว้างเพิ่มน้อย (ตารางไม่เพิ่มคอลัมน์/density option) — ไม่ใช่ bug แต่เป็นโอกาส (เช่น density "comfortable/compact", ตารางใช้ที่ว่างมากขึ้น)

## 4. TOUCH UX AUDIT

| เกณฑ์ | ผล |
|---|---|
| Touch target ≥44px | ปุ่มหลัก ✅ (admin `btn` 44 / public `btn` 48), field ✅ (44/48) · **❌ `btn-sm` 36px (admin), pagination `h-9 w-9` 36px, ไอคอน header `h-9 w-9`** |
| Thumb reachability | ✅ bottom-nav อยู่ล่าง (โซนนิ้วโป้ง), action หลักล่าง, StickyCTA ตรึงล่าง |
| Bottom navigation | ✅ 5 ช่อง center เด่น + หุบ/ขยายตามเลื่อน |
| Gesture | ✅ swipe เปลี่ยนรูปการ์ด (`touch-pan-y` กันชน carousel), snap carousel, pull-to-refresh |
| Scroll | ✅ `overscroll-contain` ใน modal/เมนู, scroll-smooth, scrollbar ซ่อนใน carousel |
| Touch feedback | ✅ `active:scale-[0.98]` (เพิ่ง A4), `active:bg-canvas` การ์ด |

**🔴 ประเด็นเด่น = touch target 36px** (`btn-sm` ใช้ 27 จุด, pagination, ไอคอน header). มาตรฐาน Apple 44px / Material 48dp → ควรดันเป็น ≥40–44 บน touch

## 5. MOUSE UX AUDIT — **A−**
- hover ใช้ **86 จุด (admin) / 41 (public)** — เยอะแต่เป็น *enhancement* ไม่ใช่ affordance เดียว
- **ไม่มี hover-dependency บน touch:** ลูกศรรูปการ์ด public = `opacity-100` บนมือถือ → `sm:opacity-0 sm:group-hover:opacity-100` บน desktop (เห็นเสมอบนสัมผัส) ✅
- click area: ทั้งแถว/ทั้งการ์ดกดได้ (`onRow`), cursor-pointer, `PhoneLink` หยุด event กันชนแถว ✅
- ไม่มี custom context menu (ใช้ ConfirmDialog/ปุ่มแทน) — เหมาะ, ไม่ทับ native

## 6. KEYBOARD UX AUDIT — **B+**
- **Focus indicator: มีระดับ global ใน `globals.css` ทั้งสองแอป** (สำคัญ):
  `a/button/input/select/textarea/[tabindex]/[role=button]:focus-visible { outline: 2px gold }`
  → คีย์บอร์ดเห็นชัดทุก control, ไม่ขึ้นตอนคลิกเมาส์ ✅
- tab order = ลำดับ DOM ธรรมชาติ (ฟอร์มเรียงบนลงล่าง, modal footer ตรึง) ✅
- aria-label 20/14, role 5/4, aria-expanded (FilterBar) ✅
- **ช่องว่าง:** ยังไม่มี keyboard shortcut (n/⌘K), ไม่มี skip-to-content link, ไม่มี `aria-current` บนเมนู active, ไม่มี focus-trap ที่ประกาศชัดใน Modal (พึ่ง DOM order)

## 10. สรุป + กลยุทธ์
> **สถานะ Sprint 0.5 (2026-06-24): ทำ + เทสแล้ว — รายการ ✅ ด้านล่าง**

### 🔴 ต้องแก้ด่วน (touch target)
1. ✅ **เสร็จ** — ดัน touch target ≥40px บนสัมผัส: `btn-sm` (media `any-pointer:coarse`→2.5rem), pagination + NotificationBell (`touch:h-10/w-10`), ปุ่ม + เพิ่มทรัพย์ & ไอคอนค้นหามือถือ (`h-10 w-10`) · เดสก์ท็อปเมาส์คง 36px · ยืนยันใน compiled CSS
2. ✅ **เสร็จ** — `aria-current="page"` บนเมนู active (rail + drawer + bottom-nav) · typecheck ผ่าน

### ⚡ Quick Wins (≤1 วัน, UI-only)
- ✅ **เสร็จ** — skip-to-content link (`ข้ามไปเนื้อหาหลัก`) + `id="main-content" tabIndex=-1` ทั้งสองแอป · ยืนยัน render บน public
- ✅ **เสร็จ (เลือกตัวเลือก ก) 2026-06-25** — contrast `faint #A8A29E` บน canvas = 2.40:1 (ตก AA). แก้โดย: ข้อความที่สื่อความหมายทั้งหมด (SectionLabel, dt labels, hints, counts, table headers, timestamps, units, status text) → `muted #78716C` = **4.57:1 ผ่าน AA** · คง `faint` ไว้เฉพาะ **ไอคอน + placeholder** (ตกแต่ง). กวาด ~50 จุด/29 ไฟล์ (sed เฉพาะบรรทัดที่ไม่มี Icon) + ui.tsx targeted. ยืนยัน: computed color labels = rgb(120,113,108)=muted, typecheck ผ่านทั้งสองแอป, screenshot หน้า settings อ่านง่ายขึ้น ไม่พัง
- 🟢 **เหลือ (minor)** — ลูกศรเลื่อนรูปใน `PropertyCard` (public) = `h-8 w-8` (32px); การเลื่อนหลักบน touch คือ swipe อยู่แล้ว → ดันเป็น 40px ได้ถ้าต้องการ

### 🛠️ Long-term
- iPad landscape (touch + จอ ≥1024): *option* สลับเป็น sidebar (ผู้ใช้เลือกได้) — เคารพ touch-first เป็น default
- keyboard shortcuts + command palette ⌘K (Sprint 3/F2)
- density toggle สำหรับ large desktop (ตาราง comfortable/compact)
- focus-trap ที่ประกาศชัดใน Modal (จับ Tab วนในกล่อง + คืน focus ตอนปิด)

### 🎯 Recommended Responsive Strategy (ยืนยันทิศที่ระบบใช้อยู่)
> **คงสถาปัตยกรรม 2 แกนไว้ — มันถูกต้องแล้ว:**
> - `sm:`/`lg:` = fluid layout ภายใน shell
> - `mouse:`/`touch:` = สลับ shell ตาม **input method** (ไม่ใช่แค่ความกว้าง)
>
> เป้าหมาย ONE DESIGN SYSTEM **บรรลุแล้ว** (token/component/data ชุดเดียว). งานที่เหลือคือ *ขัด touch target + a11y* ไม่ใช่รื้อ responsive
